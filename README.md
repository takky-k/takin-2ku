# takin' 2ku

iPhoneの縦画面を中心に使う、日本語の筋トレ管理PWA。**v1.3：コンパクトな自動保存のセット表、睡眠の起動・復帰時更新、日付指定の実績取込**に対応したローカル版です。React / TypeScript strict / Vite / Tailwind CSS / Dexie / Recharts / Zustand / Zodを使用します。必須の有料サービス、Apple Developer Program、LLM API、Firebase設定はありません。

## 起動・検証（Windows対応）

Node.js 22.12以上とGitを使用します。

```powershell
npm ci
npm run dev
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

開発URLは `http://127.0.0.1:5173/takin-2ku/`、ビルドの確認は `npm run preview` です。Service Workerは本番ビルドで有効になるため、オフライン確認にはpreviewを使います。依存バージョンはpackage-lock.jsonで固定します。

## 現在の機能

- Luxury Monochromeのダーク/ライトUI。下部は今日 / 記録 / 履歴 / 分析 / AI、設定は右上、進行中の記録へ戻るリンク。
- 上半身A（13セット）/B（12セット）の指定予定値、週4回・lbが初期設定。脚をデフォルトに追加しない。種目順・重量・回数をセットごとに編集。編集ボタンは独立した画面へ遷移。複製ボタンとデモボタン、今日の画面の装飾的な文章は除去しました。
- 元のAと内容が完全一致する未使用の「コピー」は更新時にソフトデリート。編集されたものや実施記録のあるメニューは保持し、削除直後は「元に戻す」も利用できます。
- 永続フォームメモ・動画リンクを記録欄の近くに常時表示。通常のコンテンツと一緒にスクロールし、固定表示しません。今回だけのメモとは別保存。シュラッグは自動増量・回数変更なし。
- 種目・マシン・重量基準・メモの管理。同名でも種目IDで区別。
- セッション内の種目追加・削除・並べ替え。過去の名称・マシン・メモをスナップショットで保持。
- 種目ごとに「SET / 重量 / REPS / RIR / 削除」のコンパクトな表。重量・回数は数値キーボード、範囲記号も入力するRIRは文字キーボード。完了チェック・三点メニュー・セット種別選択はありません。回数を入力し値が有効なセットだけ実績へ自動反映。未入力の予定回数はプレースホルダーとして区別します。追加行は重量だけ継承し、回数・RIRは空欄。削除は最終行の×のみ、直前削除を取り消せます。セットメモは必要時に展開します。
- RIRの空欄はnull、0は `{min:0,max:0}`。0〜10の0.5刻みと `1~2` / `1〜2` の範囲。開始時の実測RIRは未入力で、予定・前回のRIRを自動で実測値にしません。
- 同じ種目・機器の前回と前週同曜日を参照。別機器・機種未確認のCSV履歴は参考として区別し、一定比率で換算しない。
- 入力の都度IndexedDB保存。書き込み前のセット入力をローカルの補助記録へ残し、即時再読み込みでも復元。削除済みセットは復活させず、別編集と競合したら停止します。入力途中の不正なRIRが残る場合は終了を確定しません。
- 休憩タイマーは30秒 / 1分 / 1分30秒 / 2分 / 2分30秒。終了時刻から復元します。
- 気分・筋肉疲労・部位別の筋肉痛は両端の意味を示すスライダー。触らない値は未入力のまま。「保存」後もフォームを維持し、同じ日への再保存は上書き。今日の体重・痛みの入力欄は除去。体重は終了後だけ記録し、過去の痛みや体重のデータは保持します。
- 「今日のトレーニングメモ」は、保存したコンディション、前回実施、同じ機器の直近実績から生成するローカル分析。小標本で停滞を断定せず、ユーザーの記録は書き換えません。今回だけの種目メモ入力は非表示です。
- 履歴の日付/種目フィルタ、詳細、編集、ソフトデリート。
- 重量/回数/推定1RMの期間別グラフ、週間の筋群別セット数と頻度、週間目標バー。推定1RMは1〜12回のみ。体型の達成率や個人予測精度は未推定と表示。
- 外部AI不要のローカル提案。重量の増加上限は2.5%かつ2.5kg、履歴に根拠がなければ重量刻みを創作しない。痛み・強い疲労・筋肉痛・取得した6時間未満の睡眠で増加しない（ローカルの保守的ルール）。睡眠から具体的な性能低下量を推測しません。承認時に状態を再検証し、当該セッションの未完了セットのみ更新。テンプレート・過去の実績は変更しない。
- kg/lb表示切替、内部保存はkg。既存のデモDBは実データから分離して保持していますが、通常UIのデモ切替はありません。
- JSON全エンティティのエクスポート、検証・プレビュー付きインポート、ID重複検出、競合は既存を保持して件数を報告。実績CSV出力も利用可能（完全なID・機器・メモ・体重などの復元にはJSONを使用）。CSVは計算式として解釈され得る文字列を保護します。
- インストール可能なPWA、オフラインシェル、起動・復帰・オンライン復帰で新バージョンを確認し、本人確認後に更新。トレーニング中は更新を抑止。

## 保存と将来の同期

`src/model.ts` がデータ契約、`src/db.ts` が原子的な保存・バックアップ・移行、`src/training.ts` がセッション操作、`src/recommendations.ts` が提案と承認時の安全検証、`src/csv.ts` が履歴移行です。

全ドメインレコードに `id / schemaVersion / createdAt / updatedAt / deletedAt / clientId / revision` を付与。日時はISO8601 UTC、表示は端末ローカル時刻。セッションに種目情報を複製し、テンプレート変更で過去記録を書き換えません。ローカル変更とSyncOperationは同じDexieトランザクションで確定し、削除はtombstoneを保持します。

DB名は `takin-2ku` と `takin-2ku-demo`。現在はschema v3。v1の数値RIRをmin/max形式に移行し、v2からは既存記録を維持してCSV原文・取り込み履歴を追加します。JSON v1/v2も移行し、未知の版・不正な値・ファイル内の重複ID・セットの参照不整合を拒否。復元は全体をトランザクション処理し、既存IDの異なる内容を自動上書きしません。同期キューはドメインレコードから再構築します。既存ユーザーのメニューは自動上書きせず、設定から不足するA/Bを追加できます。

## 履歴CSVの安全な取り込み

設定 → 履歴CSVファイルを選択 → マッピング・実績候補/要確認/重複をプレビュー → 確認して取り込む。UTF-8、BOM、引用符、セル内改行に対応。列は `日付,種目,セット番号,重量,重量単位,回数,RIR,メモ,データ区分,確認状況`。

- 元の全列・文字列、入力重量/単位、RIR原文/確度、確認状況・行番号を保存。日付しかない場合は時刻を不明として表示・集計し、所要時間を捏造しません。
- 空欄RIRはnull、0と範囲はそのまま保持。「限界」「12-13回」、不明重量、範囲外RIR、矛盾や暫定名称の記録は原文を保留し、分析やAIの根拠から除外します。
- 要件書にある予定表と一致する行は、CSVが実績と表示していても要確認にします。この曖昧さだけが残る行は、本人が実績と明示確認した後に取り込み可能。保留後も原文一覧から確認できます。
- 元CSVには機種・片側/合計の列がないため、機種と重量基準を未確認として分離。明示した名称対応（例：リアデルト→リアデルトマシン）以外の種目を勝手に統合しません。
- 日付/元種目名/セット番号から安定IDを作り、ファイル名変更・再送でも重複を防止。既存IDと内容が異なる場合は競合として保持し、上書きしません。
- 行・セッション・セット・同期キューを原子的に保存。ストレージエラー時は全体をロールバック。取り込みの取り消しはtombstone方式で、取り込み後に編集されたセットがあれば停止します。取り消した行の自動復活は行いません。
- 保留中の不明な回数/重量などをアプリが推測して確定する機能はありません。原記録の確認が必要です。全原文はJSONバックアップにも含まれます。

**個人のCSV実ファイルや実績データはリポジトリ・配信アセットに含めません。** ファイルは端末内で処理し、外部へアップロードしません。PCからiPhoneへのデータ移行には本人がファイルを移して取り込むか、JSONバックアップを利用してください。現時点では端末間の自動同期はありません。

Phase 2用のSyncAdapterとAI provider interfaceを分離しました。Health・予測/実績・説明根拠・体調データの保存先も予約しています。**Firebase SDKを接続せず、Auth・Firestoreへの通信/書き込みは一切行いません。** `firestore.rules` は全拒否のままです。このファイルを自動デプロイする処理もありません。Spark維持、Blaze・カード登録要求なし。

今後の同期は認証後に `users/{uid}/{collection}/{id}` を使用し、競合解決・バックオフ・UID分離・ルールのEmulatorテストを実装します。現在のキュー件数は「将来同期する変更数」で、クラウドへの同期成功を意味しません。

## Safariの保存について

IndexedDBが利用できるSafariでは、通常/プライベートのどちらでも同じコードで保存・読み込みます。ただし**プライベートセッション終了時の消去、OS/ブラウザーによる保存領域解放はPWAから防げません**。永続保存APIの可否を案内し、DB書き込み失敗は明示します。定期的なJSONバックアップが必要です。保存できない環境を「保存済み」として扱いません。

ホーム画面への追加：Safariで公開URLを開く → 共有 → ホーム画面に追加。初回はオンラインでService Workerのキャッシュ完了を待ちます。

## 睡眠ショートカット・ロゴ

「今日のコンディション」または設定から、ショートカットが出力した睡眠JSONを検証・プレビューして取り込めます。`public/shortcuts-sleep.html` にiPhone側の手順と交換形式を記載。実ショートカットのJSONサンプルは未受領で、受け渡し方法も未設定です。未知の形式は拒否し、サンプル確認後にフィールド・睡眠段階の対応表を設定可能。日付を省略した対応表では区間終了の端末ローカル日を使用します。夜間で分割された睡眠は起床日を明示して渡してください。

起動・フォアグラウンド復帰・オンライン復帰・日付変更時に保存済みの睡眠を再取得。同じ区間は重複保存せず、重なる睡眠段階を和集合で集計し、覚醒・就床中を加算しません。取得成功/本日データなし/連携未設定/取得失敗の4状態を表示し、欠測はnullのまま。保存済みの睡眠はローカル提案・トレーニングメモに反映します。

任意の自動取得先は設定画面で登録。**本人専用の認証・CORS対応HTTPS GET APIが既に用意された場合だけ**、Bearerトークン付き・Cookieなし・リダイレクト拒否で新しいJSONを確認します。APIは自動作成しません。API側は認証/本人制限/保存データの保護が必要で、Pagesは受信処理を実行できません。トークン・URLは端末だけへ保存し、JSONバックアップに含めません。無料のファイル取込だけでも使用可能です。

**iPhone側でのショートカットの共有・権限許可・実JSONとの接続は未完了**です。PWAがApple Healthやローカルファイルを直接自由に読むことはできません。Healthへの書き込みは行いません。

## 本人の実績を非公開で取り込む

設定 →「日付指定のトレーニング取込」で本人用JSONを選択 → 日付・種目数・セット数を確認 →「確認して実績を保存」。取込ファイルは公開リポジトリやPagesへ含めず、ローカルの `exports/` に保管します。本人のChromeやiPhoneのDBは端末ごとに独立しているため、コードのデプロイだけでは記録を登録できません。

既存の種目IDを名称・機器IDから再利用し、曖昧なら書込み前に停止します。日付と全セットの種目/機器/順序/重量/回数が一致する既存実績にはRIRと前回比較メモのみを修正。他の履歴や本人メモを保持。同じ取込IDは一度だけ実行し、トランザクション失敗時は全体をロールバックします。比較メモは別フィールドで保持し、日付不明の別セッションを作成したり統計に加算したりしません。時刻不明の実績は `timePrecision: date` として保存します。

DBバージョン4では未完了セットに生入力の状態を追加し、完了済みセット・RIR 0・メモを変更しません。ドメイン/JSONバックアップのschemaVersionは互換性のある追加項目として3を維持します。

提供されたT2ロゴをヘッダー、favicon、PWA/Appleホーム画面アイコンに使用。加工元・加工内容は `assets/brand/README.md`、派生サイズの生成は `node scripts/prepare-brand.mjs`。大きいマスター画像は配信せず、小さい派生PNGだけを配信します。

## GitHub Pages

対象リポジトリは **takky-k/takin-2ku**。仕様の古い例にある `liftlog-ai` は使用しません。

1. GitHubのリポジトリ Settings → Pages → Build and deployment → Source を **GitHub Actions** に設定。
2. この変更をmainへマージ（またはmainへpush）。`.github/workflows/deploy.yml` が `npm ci → build → test → Playwright → Pages deploy` を実行。
3. Actionsの緑の完了を確認後、`https://takky-k.github.io/takin-2ku/` を開く。
4. iPhone Safariでホーム追加、機内モードで起動・記録・再起動・JSON復元を確認。

Vite base・manifestのscope/start_url・Service Workerのナビゲーション対象をすべて `/takin-2ku/` に統一。HashRouterなので `/#/history` 等の再読み込みでPagesの404を回避します。ロールバックはmainの変更をrevertして再デプロイします。PublicリポジトリとGitHub標準ホストランナーの無料構成です。
