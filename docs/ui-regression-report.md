# v1.4 タブ整理・開始目標・非公開コード取込

- 今日をコンディションだけに整理。記録に既存マイメニューを移し、週間回数を分析先頭に配置。履歴タブは削除し、分析から過去の記録へアクセス可能。
- 開始時に最新の同機器実績と保存済みコンディションからローカル目標を生成。承認前に実績入力表を出さず、承認後も回数/RIRの実績は空欄を維持。全種目の承認は原子的に適用し、直前に疲労が強まった場合は全体を停止。
- 低い気分・強い疲労・短時間睡眠では前回実績と予定を上回る増加を避ける。固定種目の安全上限の基準も修正。
- 二重開始の同時実行を防止。テンプレートと過去の実績は変更しない。
- 取込コードは端末内だけで展開。個人のコードをURL・GitHub・Pagesへ含めない。既存の原子的・冪等な取込処理を再利用。
- Vitest 60件と390px Chromium E2E 8件で、取込後に今週1回になること、再取込でも1回のまま、コンディション/前回実績からの目標を承認後に適用、リロード後も保持を確認。
- iPhone実機への操作はユーザーによるコード貼付けが必要。ChromeのログインだけでIndexedDBは同期されない。

# v1.3 回帰検証

- 完了チェックなしで自動記録。未入力の予定セットは実績に含めず、生入力・旧下書きを保存/復元。
- 最終行のみ削除、追加行の回数/RIRは空欄。メモは展開式、フォームメモは固定しない。
- 公開前CIと繰り返しテストで、終了後体重欄が消える問題と連続入力を競合と誤判定する問題も再現。終了後の直近セッション欄を保持し、自分の保存完了を待ってからジャーナルを復元。途中までDBへ保存済みの連続入力も復元する回帰テストを追加。
- 見つけた回帰：旧RIR下書きの終了検証漏れ、再マウント時の部分入力の消失、単位表示の丸めによるkg誤差。修正して専用テストを追加。
- 睡眠は4状態、起動/復帰時の再読込、任意の認証HTTPS取得、同時取得/重複防止。実際の受け渡しは未設定、実JSONは未受領。
- 本人用実績は公開せず、原子的・冪等な取込処理を追加。合成データで既存ID再利用、RIR修正、本人メモ保持、ロールバックを確認。
- DB v3→v4で完了済み履歴とRIR 0を変更せず、未完了セットの生入力状態を追加。
- 最新の同種目/機器の実績をローカル提案へ使用し、取得した短時間睡眠や承認直前の体調変化を再検証。予測性能の減少量は作らない。
- 単体/React UIテスト55件、Chromium E2E7件が成功。390pxでセル編集/追加/削除/Undo/再読込/終了後体重/履歴/AIを確認。
- 実際のService Workerを2版で検証し、新しいHTMLキャッシュへ切替後もIndexedDBの履歴を保持。更新後にオフライン再起動も成功。
- iPhone実機のSafari/ホーム画面/プライベートモードと、Apple Shortcutsとの実データ接続は未検証。
- Browser plugin not available のため、プロジェクトのPlaywrightを使用。Windows Computer UseはURL判定ができず停止したため、本人用Chromeへの実績取込は自動実行していない。

# v1.2 UI改善・不具合の回帰検証

## 修正した問題

| 操作・問題                                                           | 対応                                                                                    | 確認方法                                                              |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| メニュー編集が画面下のフォーム表示だけで、押しても変化が分かりにくい | 専用URLへ遷移。画面先頭を表示し、保存後はマイメニューへ戻る                             | 新規作成・既存編集でURLと見出しの可視範囲をE2E確認                    |
| セット完了の直後に再読み込みすると、非同期保存前の完了状態が失われる | IndexedDB前の補助記録を再起動時に復元。削除済みセットは復活させず、別編集との競合は停止 | 通信遮断中の即時再読み込み、RIR 0/null/範囲、書き込み失敗の復旧を確認 |
| 入力途中のRIR `1~` があるまま終了できる                              | 完了確定前に入力途中の文字列を検証し、不正値を拒否                                      | 途中範囲を残して確定するとactiveのままになる単体テスト                |
| 保存済みの古い入力下書きが、承認後の数値を隠す可能性                 | 正常に保存した下書きは、その後の入力と一致するときだけ消去                              | 手動編集後に提案を承認し、新しい回数を表示するE2E                     |
| 終了操作の二重実行で終了時刻が再更新される                           | 終了済みセッションの再確定を冪等化                                                      | 時刻を1分進めて再実行しても元の終了時刻を維持                         |

## 要望に合わせた仕様変更

- デモ・複製ボタン、今日の装飾文章、セット種別、RIR候補ボタン、今回の種目メモを通常UIから除去。
- セットは4列表でキーボード入力。RIRは0と未入力を区別し、0.5刻み・範囲も保持。
- コンディションは意味を明示したスライダー。触らない項目は未入力。保存後もフォームを残し、再保存は同じレコードへ上書き。
- 誤コピーのAは完全一致・未使用のみ削除。編集済み・記録で使われたメニューは保持し、元に戻す操作も検証。
- 今日のコンディションと前回までの実績から、外部通信なしの全体メモを生成。少数の記録で停滞を断定しない。
- 休憩は30/60/90/120/150秒。提供されたT2ロゴはヘッダーとPWAアイコンへ適用。
- 睡眠JSONはプレビュー、重複防止、区間の重複集計防止を実装。取り込める睡眠がない間は未連携の説明を維持。

## 再現手順

```powershell
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

単体・React UIテスト41件、Chromium E2E 6件。テストは合成データと独立したDBのみを使用。個人のCSV・実記録はコミットしません。

回帰テストは失敗した操作を修正してから再実行しています。iPhone実機のSafari、Apple Shortcutsの本人設定・権限許可、完全自動同期は未検証/未完了です。睡眠JSONのテスト成功を、実機のHealth連携完了とは表現しません。
